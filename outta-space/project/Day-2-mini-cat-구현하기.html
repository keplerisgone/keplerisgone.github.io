Day 2: mini cat 구현하기 ​

이번 실습의 목표는 표준 C 파일 입출력 함수인 fopen(), fgets(), fclose() 대신 Linux 파일 입출력 시스템 콜을 사용해 간단한 cat 명령어를 구현하는 것이다.

man cat으로 명령어 알아보기 ​

우선 cat을 구현하기 위해서, cat이 어떤 명령어인지 알아볼 필요가 있다. 이를 man으로 확인해보자.

man cat

cat은 파일의 내용을 연결하여 표준 출력으로 보내는 명령어다. 이름도 concatenate에서 유래했다.

가장 기본적인 사용법은 다음과 같다.

cat hello.txt

이 명령을 실행하면 hello.txt의 내용이 표준 출력에 표시된다. 터미널에서 실행했다면 표준 출력은 일반적으로 터미널 화면이다.

여러 파일이나 옵션을 처리하는 것도 가능하지만, 이번 mini-cat에서는 범위를 단순하게 제한했다.

  • 하나의 파일만 입력받는다.
  • 옵션은 처리하지 않는다.
  • 표준 입력은 처리하지 않는다.
  • 행 번호 같은 부가 기능은 제공하지 않는다.
  • 파일 내용을 표준 출력으로 그대로 전달한다.

따라서 구현할 프로그램의 실행 형식은 다음과 같다.

./mini-cat hello.txt

기본 이론 ​

File descriptor ​

File descriptor, 줄여서 FD는 프로세스가 열어 놓은 입출력 대상을 식별하기 위해 사용하는 음이 아닌 정수다.

일반적으로 프로세스가 시작될 때 다음 FD가 준비되어 있다.

  • 0: 표준 입력
  • 1: 표준 출력
  • 2: 표준 에러

파일을 open()하면 커널은 해당 파일을 관리하고, 프로그램에는 그 파일을 식별할 수 있는 FD를 반환한다.

예를 들어 입력 파일을 열었을 때 3이 반환됐다면 다음과 같은 관계가 만들어진다.

FD 3 → 입력 파일

그 후에는 파일 경로 대신 이 FD를 read()와 close()에 전달한다.

다만 새로 연 파일의 FD가 언제나 3이라고 보장되지는 않는다. 일반적으로 현재 사용 가능한 가장 낮은 FD가 반환되기 때문에 0, 1, 2가 사용 중이라면 흔히 3이 반환되는 것이다.

시스템 콜 ​

시스템 콜은 사용자 프로그램이 커널에 기능을 요청하기 위한 인터페이스다.

파일을 열거나 데이터를 읽고 쓰는 작업은 운영체제가 관리하는 자원에 접근해야 하므로 커널의 도움이 필요하다.

이번 구현에서는 다음 문서를 확인했다.

man 2 open
man 2 read
man 2 write
man 2 close

man page의 section 2는 시스템 콜을 다룬다. 각 문서에서는 주로 다음 항목을 확인했다.

SYNOPSIS
RETURN VALUE
ERRORS

open() ​

open()은 파일을 열고 성공하면 해당 파일을 식별하는 FD를 반환한다.

파일을 읽기 전용으로 열 때는 O_RDONLY 플래그를 사용한다.

  • 성공: 음이 아닌 file descriptor
  • 실패: -1

이번 프로그램에서는 명령행 인자로 받은 파일 경로를 open()에 전달한다. 반환값이 -1이면 파일이 존재하지 않거나 접근 권한이 없는 등의 문제가 발생한 것이다.

read() ​

read()는 FD가 가리키는 대상에서 데이터를 읽어 버퍼에 저장한다.

세 인자의 의미는 다음과 같다.

  • 첫 번째 인자: 읽을 대상의 FD
  • 두 번째 인자: 읽은 내용을 저장할 버퍼
  • 세 번째 인자: 최대 몇 바이트를 읽을 것인지

반환값은 반드시 구분해서 처리해야 한다.

  • 양수: 실제로 읽은 바이트 수
  • 0: EOF
  • -1: 오류

read()의 반환형은 ssize_t다. 오류를 나타내는 -1을 표현해야 하기 때문에 unsigned 타입을 사용할 수 없다.

또한 read()는 버퍼를 C 문자열로 만들어주지 않는다. 데이터 뒤에 널 문자 '\0'을 자동으로 붙이지 않는다.

이번 구현에서는 버퍼를 문자열 함수에 전달하지 않고, read()가 반환한 바이트 수만큼 write()하기 때문에 널 문자가 필요하지 않다.

write() ​

write()는 버퍼에 있는 데이터를 지정한 FD로 출력한다.

  • 첫 번째 인자: 출력 대상의 FD
  • 두 번째 인자: 출력할 데이터가 있는 버퍼
  • 세 번째 인자: 출력할 바이트 수

파일 내용을 표준 출력으로 보내기 위해 첫 번째 인자로 STDOUT_FILENO를 사용했다. 이 값은 표준 출력 FD인 1을 의미한다.

특히 write()에는 버퍼 전체 크기가 아니라 직전 read()가 실제로 읽은 바이트 수를 전달해야 한다.

예를 들어 100바이트 버퍼에서 마지막 read()가 17바이트를 읽었다면 write()도 17바이트만 출력해야 한다. 100바이트를 출력하면 이번에 읽지 않은 버퍼 영역까지 함께 출력될 수 있다.

write()도 실패하면 -1을 반환한다. 또한 오류가 아니더라도 요청한 바이트 수보다 적게 쓸 수 있는데, 이를 partial write라고 한다.

이번 기본 구현에서는 -1 오류를 처리하고 partial write 처리는 추후 개선할 TODO로 남겼다.

close() ​

close()는 사용이 끝난 FD를 닫는다.

  • 성공: 0
  • 실패: -1

열린 FD를 계속 닫지 않으면 FD 누수가 발생한다. 장시간 실행되는 프로그램에서는 프로세스가 열 수 있는 FD 개수 제한에 도달할 수도 있다.

close()가 성공해도 FD를 저장한 C 변수의 값이 자동으로 0으로 변하지는 않는다. 변수에는 기존 번호가 남지만, 해당 FD는 더 이상 유효한 열린 입출력 대상으로 사용하면 안 된다.

fopen()과 open()의 차이 ​

fopen()은 표준 C 라이브러리 함수로, 성공하면 FILE * 스트림을 반환한다. 사용자 공간 버퍼링을 제공하며 fgets(), fprintf(), fclose() 같은 함수와 함께 사용한다.

반면 open()은 저수준 POSIX 파일 인터페이스로, 성공하면 정수형 FD를 반환한다. 이후 read(), write(), close()와 함께 사용한다.

이번 실습에서는 Linux의 저수준 파일 입출력 흐름을 이해하기 위해 open() 계열을 사용했다.

mini-cat 구현하기 ​

구현한 전체 코드는 다음과 같다.

c
#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>
#define BUF_SIZE 100

int main(int argc, char* argv[]) {
	if (argc != 2) {
		fprintf(stderr, "usage: ./mini-cat [file path]\n");
		return 1;
	}

	int fd;

	// open 및 에러 검사 (출력이 -1)
	fd = open(argv[1], O_RDONLY);
	if (fd == -1) {
		fprintf(stderr, "error: file open\n");
		return 1;
	}
	
	// buf & read result;
	char buf[BUF_SIZE];
	ssize_t result_r = read(fd, buf, BUF_SIZE);
	ssize_t result_w;

	while(result_r > 0) {
		result_w = write(STDOUT_FILENO, buf, result_r);
		if (result_w == -1) {
			fprintf(stderr, "error: file write\n");
			close(fd);
			return 1;
		}
		result_r = read(fd, buf, BUF_SIZE);
        }

	if (result_r == -1) {
		fprintf(stderr, "error: file read\n");
		close(fd);
		return 1;
	}

	
	if (close(fd) == 0) {
		return 0;
	} else { 
		fprintf(stderr, "file r/w failed\n");
		return 1;
	}
}

프로그램의 전체 흐름 ​

구현 전에 프로그램의 처리 순서를 먼저 정리했다.

  • 명령행 인자 검사
    • → 입력 파일 열기
    • → 고정 크기 버퍼로 파일 읽기
    • → 실제 읽은 바이트 수만큼 표준 출력에 쓰기
    • → EOF까지 반복
    • → 입력 파일 닫기
    • → 종료 상태 반환

데이터의 이동만 표현하면 다음과 같다.

  • 입력 파일 FD
    • → read()
    • → 메모리 버퍼
    • → write()
    • → 표준 출력 FD

명령행 인자 검사 ​

이번 프로그램은 파일 하나만 입력받는다. 따라서 필요한 인자 개수가 아니라면 사용법을 표준 에러로 출력하고 실패 상태로 종료한다.

오류 메시지를 표준 출력에 쓰지 않은 이유는 파일 내용과 프로그램의 오류 메시지가 섞이는 것을 방지하기 위해서다.

  • 표준 출력: 입력 파일의 내용
  • 표준 에러: 사용법과 오류 메시지

파일 열기 ​

명령행 인자로 전달받은 파일 경로를 읽기 전용으로 연다.

open()의 반환값이 -1이면 오류 메시지를 표준 에러로 출력하고 실패 상태로 종료한다. 파일 열기에 성공한 이후부터는 반환된 FD를 이용해 파일을 읽는다.

반복해서 읽고 쓰기 ​

고정 크기 문자 배열을 버퍼로 준비한 뒤 read()를 반복해서 호출한다.

반환값이 양수라면 그만큼의 데이터를 읽은 것이므로, 해당 바이트 수를 그대로 write()에 전달한다.

  • read() > 0: 읽은 만큼 출력하고 다시 읽기
  • read() == 0: EOF이므로 반복 종료
  • read() == -1: 오류 처리

여기서 중요한 점은 read()를 반복문 밖에서 한 번만 호출해서는 안 된다는 것이다. 다음 데이터를 처리하려면 반복할 때마다 다시 read()를 호출해야 한다.

또한 while (result)처럼 검사하면 -1도 참으로 평가되므로, 읽기에 성공한 경우를 나타내는 result > 0 조건을 사용해야 한다.

오류 처리와 자원 정리 ​

파일을 연 이후 read()나 write()가 실패하면 프로그램을 종료하기 전에 열린 입력 FD를 닫아야 한다.

사용법 및 오류 메시지는 fprintf()와 stderr를 사용해 표준 에러로 보냈다. 정상 실행 시에는 성공 메시지를 출력하지 않았다. 성공 메시지를 표준 출력으로 보내면 원본 파일 내용 뒤에 불필 요한 문자열이 붙기 때문이다.

컴파일 ​

다음 옵션을 사용해 컴파일했다.

gcc -Wall -Wextra -Wpedantic -g mini-cat.c -o mini-cat

각 옵션의 의미는 다음과 같다.

  • -Wall: 자주 발생하는 주요 경고 활성화
  • -Wextra: 추가적인 경고 활성화
  • -Wpedantic: C 표준을 엄격하게 벗어나는 사용 경고
  • -g: 디버깅 정보 포함

컴파일 결과는 warning 0, error 0이었다.

기능 테스트 ​

다음 경우를 테스트했다.

  • 일반 텍스트 파일
  • 여러 줄이 있는 파일
  • 빈 파일
  • 존재하지 않는 파일
  • 인자 없이 실행
  • 버퍼보다 큰 파일

원본 파일과 출력 결과가 완전히 같은지는 cmp를 이용해 확인할 수 있다.

./mini-cat test.txt > output.txt
cmp test.txt output.txt
echo $?

두 파일이 같다면 cmp는 내용을 출력하지 않고 종료 상태 0을 반환한다.

존재하지 않는 파일과 인자 없이 실행하는 경우에는 의미 있는 오류 메시지가 표준 에러에 표시되고, 프로그램은 0이 아닌 상태로 종료되는지 확인했다.

strace로 시스템 콜 확인하기 ​

마지막으로 strace를 이용해 실제로 어떤 시스템 콜이 호출되는지 관찰했다.

strace ./mini-cat test.txt

출력에서 오늘 구현과 직접 관련된 호출만 확인했다.

openat
read
write
close

소스 코드에서는 open()을 호출했지만 strace에서는 openat()으로 나타났다. C 라이브러리의 open() wrapper가 내부적으로 openat() 시스템 콜을 사용할 수 있기 때문이다.

실행 결과에서는 입력 파일에 FD 3이 할당됐고, 파일 내용은 FD 1을 사용하는 write()로 출력됐다.

마지막 read()의 반환값은 0이었다. 이는 입력 파일의 EOF에 도달했다는 뜻이다. 마지막에는 입력 파일 FD에 대해 close()가 호출된 것도 확인했다.

남은 개선 사항 ​

현재 구현은 write()가 -1을 반환하는 실패 상황을 처리한다. 하지만 요청한 바이트 중 일부만 기록하는 partial write는 아직 처리하지 않는다.

이를 처리하려면 다음 흐름이 필요하다.

  • write()가 실제로 기록한 바이트 수만큼 버퍼 위치 이동
    • → 남은 바이트 수 감소
    • → 남은 바이트가 0이 될 때까지 반복

이번 실습에서는 하나의 파일을 정확히 읽어 표준 출력으로 보내는 기본 구현까지 완료하고, partial write 처리는 향후 개선할 TODO로 남겼다.
