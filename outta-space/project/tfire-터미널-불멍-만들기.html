tfire: C로 터미널 불멍 만들기 ​

터미널에서 모닥불 GIF를 아스키 아트로 재생하는 작은 프로그램 tfire를 만들었다.

sh
tfire red
tfire green
tfire blue

처음에는 GIF를 문자로 바꾸어 출력하면 끝날 것 같았다. 실제로 만들어보니 명령행 인자, 이미지의 메모리 구조, 터미널 제어, 애니메이션 시간 처리와 빌드까지 여러 개념이 연결된 프로젝트였다.

문자열과 enum 연결하기 ​

C의 enum에는 "red" 같은 문자열을 직접 저장할 수 없다. 따라서 사용자가 입력한 문자열을 strcmp()로 비교해 프로그램 내부의 enum 값으로 바꾸었다.

text
"red" → COLOR_RED → ANSI 빨간색 코드

문자열을 가리키는 포인터에는 const char *를 사용했다. 입력값과 문자열 리터럴을 수정하지 않겠다는 의도를 타입으로 나타낼 수 있었다. 잘못된 색상이 들어오면 stderr에 오류를 출력하고 0이 아닌 종료 상태를 반환했다.

픽셀을 아스키 문자로 바꾸기 ​

stb_image로 이미지를 RGB 형식으로 읽으면 픽셀들은 1차원 바이트 배열에 연속해서 저장된다. (x, y) 위치의 픽셀은 다음 관계로 찾을 수 있다.

text
pixel index = (y × image width + x) × 3

여기서 연속된 세 바이트가 각각 red, green, blue다. RGB를 문자 하나로 바꾸기 위해 사람의 눈이 초록색 밝기에 더 민감하다는 점을 반영한 정수식을 사용했다.

text
brightness = (red × 21 + green × 72 + blue × 7) / 100

0부터 255까지의 밝기는 어두운 문자부터 밝은 문자까지 배치한 문자열의 인덱스로 변환했다.

c
" .:-=+*#%@"

이미지를 줄일 때는 출력 좌표를 원본 좌표에 대응시키는 가장 단순한 nearest-neighbor 방식을 사용했다. 터미널 문자는 정사각형이 아니라 세로로 긴 편이어서 출력 높이를 약 절반으로 보정해야 원본 비율과 비슷하게 보였다.

터미널 크기에 맞추기 ​

ioctl()의 TIOCGWINSZ 요청으로 현재 터미널의 열과 행을 함께 읽었다.

  • ws_col: 터미널 너비
  • ws_row: 터미널 높이

먼저 터미널 너비에 맞춰 출력 크기를 계산하고, 계산된 높이가 화면을 넘으면 높이를 기준으로 너비를 다시 계산했다. 덕분에 창 크기가 달라도 불꽃 전체가 화면 안에 들어온다.

애니메이션 중에는 ANSI escape sequence로 커서를 왼쪽 위로 이동해 같은 위치에 다음 프레임을 덮어썼다. 매번 화면 전체를 지우는 대신 남은 영역만 정리해서 깜빡임을 줄였다. printf()의 출력이 버퍼에 남지 않도록 프레임마다 fflush(stdout)도 호출했다.

GIF는 프레임 배열이다 ​

정지 이미지는 stbi_load()로 바로 읽을 수 있지만, GIF 전체를 재생하려면 파일을 먼저 메모리에 읽고 stbi_load_gif_from_memory()에 전달해야 했다.

파일을 메모리에 읽는 과정에서 다음 표준 C 파일 함수를 사용했다.

text
fopen → fseek → ftell → rewind → malloc → fread → fclose

디코딩된 프레임들은 하나의 큰 메모리 배열에 연속해서 들어 있다. 한 프레임의 크기를 구하면 i번째 프레임의 시작 위치를 계산할 수 있다.

text
frame size = width × height × 3
frame i = frames + i × frame size

이 과정에서 포인터의 소유권도 중요하게 배웠다. frame은 frames 내부를 가리키는 포인터일 뿐 별도로 할당된 메모리가 아니다. 처음에는 frame을 해제해 invalid pointer 오류가 발생했다. 실제로 해제해야 하는 것은 할당된 배열의 시작 주소인 frames였다.

text
gif_data → 직접 malloc했으므로 free()
frames, delays → stb_image가 할당했으므로 stbi_image_free()
frame → frames 내부를 가리킬 뿐이므로 해제하지 않음

각 프레임은 GIF에 기록된 delay만큼 nanosleep()으로 기다린 뒤 다음 프레임으로 넘어간다. Ctrl-C를 받으면 반복문을 끝내고 ANSI 색상, 커서와 원래 터미널 화면을 복원하도록 신호 처리도 추가했다.

빌드하며 알게 된 점 ​

stb_image 내부에서 pow()를 사용하기 때문에 헤더를 포함하는 것만으로는 빌드가 끝나지 않았다. 링크 단계에서 undefined reference to pow가 발생했고, Makefile의 링크 명령 뒤에 수학 라이브러리 -lm을 추가해 해결했다.

기본 GIF는 GNU ld로 바이너리 오브젝트로 변환해 실행 파일 안에 포함했다. 그래서 설치 후 이미지 파일의 위치와 관계없이 tfire red만으로 실행할 수 있다. 마지막에는 make install 규칙을 만들고 사용자 명령 경로인 ~/.local/bin에 설치했다.

마무리 ​

작은 불멍 프로그램이지만 C 프로그램의 여러 층을 한 번에 경험할 수 있었다.

  • 문자열 입력을 enum으로 변환하는 방법
  • 1차원 픽셀 배열과 포인터 연산
  • 메모리를 할당한 주체에 따른 올바른 해제
  • ioctl()과 ANSI escape sequence를 이용한 터미널 제어
  • 프레임 시간, 출력 버퍼와 신호 처리
  • 컴파일과 링크의 차이, Makefile을 통한 빌드와 설치

특히 “어떤 포인터가 메모리를 소유하는가”와 “컴파일 성공과 링크 성공은 다르다”는 점이 기억에 남았다. 화면에 불꽃이 움직이는 결과가 바로 보여서 C의 낮은 수준의 개념들을 비교적 즐겁게 확인할 수 있었던 프로젝트였다.
