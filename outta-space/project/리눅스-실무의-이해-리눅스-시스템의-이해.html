컴퓨터의 구성 요소 ​

구성 요소역할예시
CPU명령 해석·연산과 시스템 제어ALU, 제어장치, 레지스터
주기억장치실행 중인 명령과 데이터 저장RAM, ROM
입력장치외부 데이터를 컴퓨터에 전달키보드, 마우스, OCR, OMR
출력장치처리 결과를 사용자에게 전달모니터, 프린터, HMD
보조기억장치대용량 데이터를 비휘발성으로 저장HDD, SSD, 광학 디스크

CPU ​

  • 레지스터: CPU 내부의 가장 빠르고 작은 임시 저장장치
  • ALU(Arithmetic Logic Unit): 산술·논리·비교 연산
  • 제어장치(Control Unit): 명령을 해석하고 각 장치의 동작을 제어

주기억장치 ​

종류특성주요 용도
DRAM집적도가 높고 비교적 느림, 주기적인 재충전 필요주 메모리
SRAM빠르고 비싸며 집적도가 낮음, 재충전 불필요CPU 캐시
ROM전원이 꺼져도 내용 유지펌웨어 저장

ROM 계열은 기록 방식에 따라 Mask ROM, PROM, EPROM, EEPROM·Flash 등으로 나뉜다. 현대 PC의 UEFI 펌웨어는 일반적으로 플래시 메모리에 저장된다.

입력장치 구분 ​

  • OMR(Optical Mark Reader): 답안지처럼 표시된 마크 판독
  • OCR(Optical Character Recognition): 인쇄·필기 문자를 문자 데이터로 변환
  • MICR(Magnetic Ink Character Recognition): 자기 잉크로 인쇄된 문자 판독

Linux 설치 전 하드웨어 확인 ​

CPU ​

  • 배포판이 CPU 아키텍처를 지원하는지 확인한다.
  • 대표 아키텍처: x86-64, ARM64, RISC-V, PowerPC 등
  • 가상 머신을 사용할 경우 Intel VT-x 또는 AMD-V 같은 하드웨어 가상화 기능도 확인한다.
  • 병렬성(Parallelism)은 여러 코어·프로세서에서 실제 계산을 동시에 수행하는 것이고, 동시성(Concurrency)은 여러 작업의 진행이 시간상 겹치는 개념이다.

메인보드와 펌웨어 ​

  • 칩셋, 저장장치 컨트롤러와 네트워크 장치 지원 여부 확인
  • 설치·부팅 문제가 있으면 UEFI 설정과 펌웨어 업데이트 확인
  • Secure Boot, 저장장치 모드와 부팅 순서 확인

메모리 ​

  • 배포판과 실행할 서비스의 최소·권장 용량 확인
  • 64비트 환경에서는 32비트보다 넓은 주소 공간을 사용할 수 있다.
  • 지원 가능한 최대 메모리는 CPU뿐 아니라 메인보드와 배포판·커널 설정에도 좌우된다.
  • swap은 메모리 부족을 보완하지만 RAM을 대체할 만큼 빠르지는 않다.

저장장치 ​

Linux에서는 저장장치도 장치 파일로 표현한다.

장치일반적인 이름 예
SATA·SAS·SCSI·USB 저장장치/dev/sda, /dev/sdb
NVMe SSD/dev/nvme0n1
오래된 IDE 장치/dev/hda

장치명은 검색 순서에 따라 바뀔 수 있으므로 영구 설정에는 UUID나 /dev/disk/by-* 링크를 사용하는 편이 안전하다.

그래픽·네트워크·입력장치 ​

bash
lspci              # PCI 장치 확인
lspci | grep -Ei 'vga|3d|display'
lspci | grep -i ethernet
lsusb              # USB 장치 확인
  • 일반적인 장치는 커널 내장 드라이버로 동작한다.
  • 최신 GPU, Wi-Fi와 특수 장치는 별도 펌웨어나 제조사 드라이버가 필요할 수 있다.
  • 네트워크 설치 전 IP 주소, 프리픽스·넷마스크, 게이트웨이와 DNS 정보를 확인한다.

RAID ​

RAID(Redundant Array of Independent Disks)는 여러 디스크를 하나의 논리 장치로 묶어 성능, 용량 또는 장애 허용성을 높이는 기술이다.

  • Striping: 데이터를 여러 디스크에 나누어 기록
  • Mirroring: 같은 데이터를 여러 디스크에 복제
  • Parity: 손실된 데이터를 계산해 복구하기 위한 정보

RAID는 백업이 아니다. 실수로 삭제하거나 손상된 데이터도 함께 반영될 수 있으므로 별도 백업이 필요하다.

RAID 레벨 비교 ​

N은 같은 크기의 디스크 수, S는 가장 작은 디스크의 용량이다.

레벨구성최소 디스크사용 가능 용량장애 허용핵심
RAID 0Striping2N × S0개빠르지만 디스크 하나만 고장 나도 전체 손실
RAID 1Mirroring2보통 S미러당 1개안정적이지만 2개 구성의 공간 효율 50%
RAID 2비트 Striping + Hamming ECC다수구성에 따라 다름구성에 따라 다름현재 거의 사용하지 않음
RAID 3바이트 Striping + 전용 Parity3(N-1) × S1개전용 패리티 디스크 사용, 거의 사용하지 않음
RAID 4블록 Striping + 전용 Parity3(N-1) × S1개패리티 디스크의 쓰기 병목
RAID 5블록 Striping + 분산 Parity3(N-1) × S1개성능·용량·안정성의 균형
RAID 6블록 Striping + 이중 분산 Parity4(N-2) × S2개RAID 5보다 안전하지만 쓰기 비용 증가
RAID 0+1Stripe 묶음을 Mirror4N/2 × S구성에 따라 다름한 Stripe 묶음 장애 후 허용성 감소
RAID 1+0Mirror 묶음을 Stripe4N/2 × S미러별 1개 가능RAID 0+1보다 일반적으로 복구와 장애 허용성이 좋음

RAID 10은 RAID 1+0을 뜻한다. 교재에 나오는 RAID 5+3 같은 표기는 표준 RAID 레벨이라기보다 여러 RAID 구성을 중첩한 특수 구성으로 이해한다.

RAID 선택 기준 ​

  • 최대 성능, 데이터 보호 불필요: RAID 0
  • 단순한 이중화: RAID 1
  • 용량 효율과 1개 디스크 장애 허용: RAID 5
  • 대용량 배열에서 2개 디스크 장애 허용: RAID 6
  • 높은 성능과 안정성: RAID 10

패리티는 장애 복구 정보이며 백업 복사본은 아니다. RAID 5·6은 고장 난 디스크를 교체한 뒤 재구축하는 동안 성능이 낮아지고 추가 장애 위험이 커질 수 있다.

링크 속도는 인코딩 오버헤드를 포함하므로 실제 데이터 전송률은 표기값보다 낮다.

SATA와 SAS ​

  • SATA: 가격과 범용성을 중시하는 PC·일반 서버용
  • SAS: 이중 포트, 확장성, 신뢰성과 연속 운용을 중시하는 기업용
  • SAS 컨트롤러는 보통 SATA 드라이브도 연결할 수 있지만, SATA 컨트롤러에는 SAS 드라이브를 연결할 수 없다.

NVMe는 PCI Express 위에서 동작하며 SATA·SAS와 다른 현대적인 SSD 인터페이스다.

시험 핵심 ​

  • CPU 구성: 레지스터, ALU, 제어장치
  • DRAM은 주 메모리, SRAM은 캐시, ROM·Flash는 비휘발성 펌웨어 저장
  • OMR은 마크, OCR은 문자, MICR은 자기 잉크 문자 판독
  • SATA·SCSI 계열은 보통 /dev/sdX, NVMe는 /dev/nvme0n1
  • RAID 0은 성능만, RAID 1은 Mirroring, RAID 5는 분산 Parity 1개, RAID 6은 Parity 2개
  • RAID 10은 Mirror 후 Stripe이며 RAID 0+1보다 일반적으로 장애 대응에 유리
  • PATA·SCSI는 병렬, SATA·SAS는 직렬
