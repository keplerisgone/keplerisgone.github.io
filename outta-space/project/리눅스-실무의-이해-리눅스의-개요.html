운영체제의 개요 ​

운영체제(OS)는 사용자와 하드웨어 사이에서 자원을 관리하고, 응용 프로그램의 실행 환경을 제공하는 시스템 소프트웨어다.

운영체제의 목적 ​

항목의미목표
처리 능력(Throughput)단위 시간에 처리하는 작업량향상
반환 시간(Turnaround Time)작업 제출부터 완료까지 걸린 시간단축
신뢰도(Reliability)작업을 정확하게 처리하는 정도향상
사용 가능도(Availability)필요할 때 시스템을 사용할 수 있는 정도향상

운영체제의 역할 ​

  • CPU, 메모리, 프로세스, 장치 I/O와 파일시스템 관리
  • 여러 사용자와 프로그램 사이의 자원 할당 및 보호
  • 오류 검사와 복구
  • 네트워크와 가상화 기능 제공
  • 사용자 인터페이스와 시스템 호출 제공

사용자 인터페이스에는 CLI, GUI, VUI, 제스처 인터페이스 등이 있다.

시스템 호출과 HAL ​

  • 시스템 호출(System Call): 응용 프로그램이 커널의 기능을 요청하는 인터페이스
  • HAL(Hardware Abstraction Layer): 하드웨어의 차이를 감추어 소프트웨어의 이식성을 높이는 계층
  • 배치 작업(Batch Job): 사용자와 실시간으로 상호작용하지 않고 정해진 시점에 일괄 실행하는 작업
text
사용자
  ↓
응용 프로그램 · 셸 · GUI · 배치 작업
  ↓ 시스템 호출
커널: 프로세스 · 메모리 · 파일 · 장치 · 보안 · 네트워크 관리
  ↓ HAL
하드웨어

운영체제의 운용 기법 ​

기법핵심
일괄 처리여러 작업을 모아 순서대로 처리
다중 프로그래밍한 작업이 I/O를 기다릴 때 다른 작업을 실행하여 CPU 유휴 시간 감소
시분할CPU 시간을 타임 퀀텀으로 나누어 여러 작업에 번갈아 할당
다중 처리여러 CPU·코어를 이용해 작업을 병렬 처리
실시간 처리정해진 시간 안에 결과를 내야 함
다중 모드여러 운용 기법을 함께 사용
분산 처리독립된 시스템을 네트워크로 연결하여 작업과 자원 공유

혼동하기 쉬운 차이 ​

  • 다중 프로그래밍: CPU는 하나여도 가능하며 CPU 활용률이 목적
  • 시분할: 짧은 시간마다 작업을 전환하며 응답성이 목적
  • 다중 처리: 실제 CPU 또는 코어가 여러 개
  • 분산 처리: 독립된 여러 시스템이 통신하는 약결합 구조

다중 처리 방식 ​

  • AMP(비대칭 다중 처리): 주 프로세서가 다른 프로세서에 작업을 지시
  • SMP(대칭 다중 처리): 여러 프로세서가 메모리와 운영체제를 공유하며 대등하게 처리
  • MPP(대규모 병렬 처리): 다수의 독립 노드가 각자의 메모리를 사용하며 통신

실시간 처리 방식 ​

  • Hard Real-Time: 제한 시간 안에 반드시 완료해야 함. 무기·항공·산업 제어 등
  • Soft Real-Time: 지연이 바람직하지 않지만 치명적 실패는 아님. 영상·음성 재생 등

교재상의 발전 과정은 다음과 같다.

text
일괄 처리 → 다중 프로그래밍·다중 처리 → 시분할 → 다중 모드 → 분산 처리

IoT 운영체제는 제한된 메모리와 전력으로 센서, 통신과 실시간 작업을 처리하는 데 초점을 둔다.

RTOS는 평균 처리 속도보다 정해진 시간 안에 예측 가능하게 응답하는 것을 중요하게 본다.

시험 핵심 ​

  • 성능 목표: 처리 능력·신뢰도·사용 가능도 향상, 반환 시간 단축
  • 시스템 호출: 응용 프로그램이 커널 서비스를 요청하는 인터페이스
  • HAL: 하드웨어 차이를 추상화하여 이식성 향상
  • 다중 프로그래밍: I/O 대기 중 다른 작업을 실행해 CPU 활용률 향상
  • 시분할: 타임 퀀텀을 사용하여 대화형 응답성 향상
  • 다중 처리: 여러 CPU·코어를 사용한 병렬 처리
  • 분산 처리: 독립 시스템을 네트워크로 연결한 약결합 구조
  • Linux: 운영체제 전체가 아니라 커널
  • IoT 운영체제의 주요 조건: 저전력, 제한된 자원, 통신, 실시간성

리눅스의 기초 ​

Linux의 의미 ​

  • 1991년 리누스 토르발스가 개발을 시작한 Unix 호환 커널이다.
  • 처음에는 커널만을 의미했지만, GNU 도구와 각종 응용 프로그램을 결합한 배포판까지 Linux라고 부르기도 한다.
  • 커널과 GNU 시스템의 결합을 강조할 때는 GNU/Linux라고 표현한다.

일반적인 특징 ​

특징핵심
이식성대부분 C로 작성되어 여러 CPU 아키텍처에서 동작
자유 소프트웨어소스 코드를 사용·연구·수정·배포 가능
Multi-User여러 사용자가 한 시스템의 자원을 함께 사용
Multiprogramming여러 프로그램을 메모리에 적재하여 병행 처리
계층적 파일시스템/를 최상위로 하는 트리 구조
Shell명령 해석, 프로그래밍과 사용자 환경 설정 제공
보안권한 기반 DAC, ACL, SELinux의 MAC 등 지원

DAC(Discretionary Access Control)는 파일 소유자가 권한을 정하는 임의 접근 제어이고, MAC(Mandatory Access Control)은 보안 정책과 등급에 따라 접근을 강제한다.

기술적 특징 ​

모놀리식 커널과 모듈 ​

Linux는 파일시스템, 프로세스, 메모리와 장치 관리 등 주요 기능을 커널 공간에서 제공하는 모놀리식 커널이다. 필요한 기능을 실행 중에 추가·제거할 수 있는 적재 가능 커널 모듈을 지원한다.

장치의 파일화 ​

Linux는 여러 시스템 자원을 파일 인터페이스로 다룬다.

  • 장치 파일: /dev 아래의 문자·블록 장치
  • 파이프: 프로세스 간 데이터 전달
  • 소켓: 로컬·네트워크 통신

파일시스템 ​

  • Linux 계열: ext2, ext3, ext4, XFS 등
  • 다른 운영체제: FAT, NTFS 등
  • 네트워크: NFS, SMB/CIFS 등
  • 저널링 파일시스템은 변경 기록을 남겨 장애 후 복구를 돕는다.

가상 메모리와 Swap ​

  • 가상 메모리: 프로세스에 독립적인 주소 공간을 제공하고 이를 물리 메모리에 매핑
  • 요구 페이징: 필요한 페이지만 물리 메모리에 적재
  • Swap Out: 메모리 내용을 디스크의 swap 공간으로 이동
  • Swap In: swap의 내용을 다시 메모리로 이동
bash
free -h                    # 메모리와 swap 사용량
sysctl vm.swappiness       # swap 성향 확인

vm.swappiness는 “메모리가 몇 % 남았을 때 swap한다”는 단순 임계값이 아니라, 커널이 익명 페이지와 파일 캐시 회수 중 swap을 얼마나 선호할지를 나타내는 값이다.

동적·정적 라이브러리 ​

구분동적 라이브러리정적 라이브러리
연결실행 시 공유 라이브러리 적재빌드 시 실행 파일에 포함
장점실행 파일이 작고 메모리 공유 가능실행 환경의 라이브러리 의존성이 적음
단점호환 라이브러리가 필요실행 파일이 크고 코드 중복 발생
bash
ldd 실행파일       # 동적 라이브러리 의존성 확인
ldconfig           # /etc/ld.so.cache 갱신

동적 링커는 /etc/ld.so.conf 계열 설정과 캐시를 사용하며, LD_LIBRARY_PATH도 검색 경로에 영향을 준다.

파이프와 리다이렉션 ​

bash
command1 | command2    # 앞 명령의 표준 출력을 다음 명령의 표준 입력으로 전달
command > file         # 표준 출력 덮어쓰기
command >> file        # 표준 출력 이어쓰기
command < file         # 파일을 표준 입력으로 사용
command 2> error.log   # 표준 오류 저장

가상 콘솔 ​

하나의 시스템에서 여러 텍스트 콘솔을 전환해 사용할 수 있다. 전환 키와 그래픽 세션의 위치는 배포판·디스플레이 관리자 설정에 따라 달라지므로 Ctrl+Alt+F1~F6, F7을 고정 규칙으로 외우지 않는다.

장단점 ​

장점단점
라이선스 비용 부담이 적고 수정 가능상용 제품에 따라 공식 기술 지원이 제한적
서버·PC·임베디드 등 다양한 환경 지원일부 상용 응용 프로그램 지원 부족
강력한 네트워크와 서버 기능제조사가 드라이버를 제공하지 않으면 지원이 늦을 수 있음
목적에 맞게 커널과 시스템을 구성 가능배포판마다 관리 방식과 환경이 다를 수 있음

GNU, 자유 소프트웨어와 오픈소스 ​

GNU ​

  • GNU는 GNU's Not Unix의 재귀적 약어다.
  • 리처드 스톨먼이 1983년 GNU 프로젝트를 시작했다.
  • GCC, Bash, Emacs, coreutils, GRUB 등 Unix 호환 자유 소프트웨어를 개발했다.
  • FSF(Free Software Foundation)는 1985년에 설립됐다.

자유 소프트웨어의 네 가지 자유 ​

번호자유
0어떤 목적으로든 프로그램을 실행
1작동 원리를 연구하고 필요에 맞게 수정
2복제본을 배포
3개선한 프로그램을 공동체에 배포

자유는 가격이 아니라 사용자의 권리를 뜻한다. 연구와 수정에는 소스 코드 접근이 필요하다.

Copyleft와 오픈소스 ​

  • Copyleft: 저작권을 이용해 수정·재배포된 결과에도 같은 자유를 유지하도록 하는 방식
  • GPL: Copyleft를 구현한 대표적인 라이선스
  • Open Source: 소스 공개뿐 아니라 재배포와 파생 저작물 등을 허용하는 라이선스·개발 방식
  • OSI(Open Source Initiative): 오픈소스 정의와 라이선스 인증을 담당하는 단체

자유 소프트웨어는 사용자의 자유를 강조하고 오픈소스는 개발 방식과 실용적 이점을 강조하지만, 실제 라이선스와 소프트웨어 범위는 상당 부분 겹친다.

주요 라이선스 비교 ​

라이선스성격파생물 소스 공개
GPL강한 CopyleftGPL 코드와 결합된 파생 저작물에 같은 라이선스 요구
LGPL약한 Copyleft, 라이브러리에 주로 사용LGPL 자체를 수정하면 공개, 단순 링크 프로그램은 일반적으로 제외
MPL파일 단위 Copyleft수정한 MPL 파일 공개, 다른 파일까지 확대하지 않음
BSD허용적의무 없음, 저작권·면책 고지 유지
MIT허용적의무 없음, 저작권·허가 고지 유지
Apache 2.0허용적, 특허 조항 포함의무 없음, 고지와 변경 사항 표시

라이선스 세부 의무는 버전과 결합·배포 방식에 따라 달라질 수 있다. 시험에서는 Copyleft의 강도를 GPL > LGPL·MPL > BSD·MIT·Apache 순으로 구분한다.

자주 묻는 배포판 ​

  • RHEL: Red Hat의 유료 기업용 배포판
  • Fedora: 빠르게 새 기술을 도입하는 커뮤니티 배포판
  • CentOS Stream: 다음 RHEL 릴리스의 변경 사항이 먼저 반영되는 업스트림
  • Rocky Linux: 기존 CentOS Linux의 대안으로 등장한 RHEL 호환 배포판
  • Debian: 안정성과 자유 소프트웨어 원칙을 중시하는 커뮤니티 배포판
  • Ubuntu: Canonical이 지원하는 Debian 기반 배포판
  • Slackware: 현존하는 가장 오래된 배포판 중 하나로 단순성과 전통적 관리 방식 강조
  • openSUSE: SUSE 계열의 커뮤니티 배포판
  • Android: Linux 커널 위에 Android 전용 런타임과 프레임워크를 구성
  • AOSP: Android의 공개 소스 프로젝트

CentOS는 Fedora의 최신 기술을 따라가지 못해 만든 배포판이 아니다. 과거 CentOS Linux는 RHEL 소스를 재빌드한 다운스트림 호환 배포판이었고, CentOS Stream은 RHEL 바로 앞 단계의 업스트림이다.

Linux의 활용 분야 ​

  • 서버와 클라우드: 웹, 데이터베이스, 네트워크 서비스와 컨테이너 호스트

  • 메인프레임과 슈퍼컴퓨터: 대규모 업무 처리와 고성능 계산

  • 스마트 장치: Android, TV, IVI와 각종 가전

  • 임베디드·IoT: 목적별 커널 구성, Raspberry Pi와 산업 장비

  • 게임: Steam, Proton을 통한 Linux용·Windows용 게임 실행

  • 포팅(Porting): 다른 운영체제나 하드웨어에서 동작하도록 소프트웨어를 이식하는 작업

  • Proton: Linux에서 Windows 게임을 실행하기 위한 Steam의 호환 계층

Linux 클러스터 ​

종류목적핵심
HPC고성능 계산여러 노드의 계산 능력을 병렬로 사용
부하 분산처리량과 확장성로드 밸런서가 요청을 여러 서버로 분배
고가용성(HA)서비스 중단 최소화주 노드 장애 시 대기 노드가 서비스를 인계

HA는 장애 시간을 줄이는 것이 목적이고, 부하 분산은 트래픽을 나누는 것이 목적이다. 두 방식을 함께 구성할 수도 있다.

Linux 기초 시험 핵심 ​

  • Linux는 커널, 배포판은 커널과 GNU 도구·응용 프로그램을 묶은 운영체제
  • 모놀리식 커널이지만 적재 가능 모듈을 지원
  • /를 루트로 하는 계층적 파일시스템과 장치의 파일화
  • 가상 메모리는 주소 공간, swap은 디스크의 교체 공간
  • GPL은 강한 Copyleft, LGPL은 라이브러리 링크에 완화, BSD·MIT·Apache는 허용적
  • Red Hat 계열은 RPM·DNF, Debian 계열은 DEB·APT
  • HPC는 계산, 부하 분산은 트래픽 분배, HA는 장애 시 서비스 지속
