1. 프로세스 생성: fork, exec ​

fork ​

현재 프로세스를 복제하여 새로운 프로세스를 생성한다.

  • 원래 프로세스 → 부모 프로세스(Parent Process)
  • 새로 만들어진 프로세스 → 자식 프로세스(Child Process)
  • 부모와 자식은 서로 다른 PID를 가진다.
bash
fork()

exec ​

현재 프로세스의 실행 내용을 새로운 프로그램으로 교체한다.

  • 새로운 프로세스를 생성하는 것이 아님
  • 기존 프로세스의 PID는 유지
  • 실행 중인 프로그램 이미지만 교체

비교 ​

항목forkexec
역할프로세스 복제실행 프로그램 교체
새 프로세스 생성OX
PID새로운 PID 생성기존 PID 유지
핵심부모 → 자식현재 프로그램 → 다른 프로그램

같이 기억하기 ​

일반적인 셸의 명령 실행은 다음과 같은 구조로 이해할 수 있다.

text
Shell
  │
  └─ fork()
       │
       └─ Child Process
              │
              └─ exec(command)

2. 프로세스와 Job ​

PID ​

Process ID.

운영체제가 각 프로세스를 구분하기 위해 부여하는 번호이다.

Job ID ​

현재 셸에서 관리하는 작업(Job)에 부여되는 번호이다.

text
PID ≠ Job ID

예:

text
[3] 513
 ↑   ↑
Job  PID
ID

fg, bg는 일반적으로 PID가 아니라 Job ID를 사용한다.

3. Job Control ​

셸에서 실행 중인 작업을 foreground와 background 사이에서 제어한다.

jobs ​

현재 셸에서 관리하는 Job 목록을 확인한다.

bash
jobs

예:

text
[1]+ Running    sleep 100 &
[2]- Stopped    vim test.txt

fg ​

Background 또는 Stopped 상태의 Job을 Foreground로 가져온다.

bash
fg %3

→ Job ID가 3인 작업을 foreground에서 실행

bg ​

중지된 Job을 Background에서 다시 실행한다.

bash
bg %3

→ Job ID가 3인 작업을 background에서 실행

nohup ​

터미널이 종료되어도 프로그램이 계속 실행되도록 한다.

bash
nohup command &

보통 출력은 nohup.out에 저장된다.

핵심 비교 ​

명령역할
jobs현재 셸의 Job 확인
fgJob → Foreground
bgJob → Background
nohup로그아웃 후에도 실행 유지

4. Signal ​

Signal은 프로세스에 특정 사건이나 명령을 전달하기 위한 소프트웨어 인터럽트이다.

표준 Signal 전체 ​

아래 번호는 리눅스마스터 시험에서 일반적으로 다루는 x86/ARM 계열 Linux 기준이다. 일부 다른 아키텍처에서는 번호가 다를 수 있으므로 이름과 역할도 함께 기억한다.

번호Signal기본 동작의미
1SIGHUP종료터미널 연결 종료(Hangup). 데몬의 설정 재로드에도 자주 사용
2SIGINT종료키보드 인터럽트(Interrupt), Ctrl+C
3SIGQUIT코어 덤프키보드 종료(Quit), Ctrl+\
4SIGILL코어 덤프잘못된 명령어(Illegal instruction) 실행
5SIGTRAP코어 덤프디버깅용 추적·브레이크포인트(Trap)
6SIGABRT코어 덤프abort()에 의한 비정상 종료(Abort)
7SIGBUS코어 덤프잘못된 메모리 접근, 버스 오류(Bus error)
8SIGFPE코어 덤프산술 연산 오류(Floating-point exception)
9SIGKILL종료즉시 강제 종료. 포착·차단·무시 불가
10SIGUSR1종료사용자 정의 Signal 1
11SIGSEGV코어 덤프잘못된 메모리 참조(Segmentation violation)
12SIGUSR2종료사용자 정의 Signal 2
13SIGPIPE종료읽는 프로세스가 없는 파이프에 쓰기(Broken pipe)
14SIGALRM종료alarm() 타이머 만료
15SIGTERM종료정상적인 종료 요청. kill의 기본 Signal
16SIGSTKFLT종료보조 프로세서 스택 오류. 현재는 거의 사용하지 않음
17SIGCHLD무시자식 프로세스의 정지·종료·상태 변화 알림
18SIGCONT계속정지된 프로세스 실행 재개
19SIGSTOP정지프로세스 강제 정지. 포착·차단·무시 불가
20SIGTSTP정지터미널에서 정지 요청, Ctrl+Z
21SIGTTIN정지백그라운드 프로세스가 터미널 입력을 시도
22SIGTTOU정지백그라운드 프로세스가 터미널 출력을 시도
23SIGURG무시소켓에 긴급(Urgent) 데이터 도착
24SIGXCPU코어 덤프CPU 시간 제한 초과
25SIGXFSZ코어 덤프파일 크기 제한 초과
26SIGVTALRM종료가상 타이머(Virtual alarm) 만료
27SIGPROF종료프로파일링 타이머 만료
28SIGWINCH무시터미널 창 크기 변경(Window change)
29SIGIO종료비동기 입출력 가능 알림. SIGPOLL과 같은 번호
30SIGPWR종료전원 장애(Power failure) 알림
31SIGSYS코어 덤프잘못된 시스템 호출(Bad system call)

기본 동작의 뜻은 다음과 같다.

기본 동작의미
종료프로세스 종료
코어 덤프프로세스를 종료하고 디버깅용 메모리 상태 기록
무시별도 동작 없이 Signal 무시
정지프로세스 실행 일시 정지
계속정지된 프로세스 실행 재개

별칭과 실시간 Signal ​

  • SIGIOT는 SIGABRT(6)의 별칭이다.
  • SIGPOLL은 Linux에서 SIGIO(29)의 별칭이다.
  • SIGUNUSED는 과거 SIGSYS(31)의 별칭으로 쓰였으나 현재 glibc에서는 정의하지 않는다.
  • 일반적인 glibc 기반 Linux에서 32번과 33번은 스레드 구현 내부용으로 예약되어 있다.
  • 실시간 Signal은 보통 SIGRTMIN(34)부터 SIGRTMAX(64)까지이다. 표준 Signal과 달리 여러 번 발생하면 큐에 쌓이며 우선순위 순서로 전달된다.
  • 시스템에서 실제 목록과 번호는 kill -l로 확인할 수 있다.

특히 구분 ​

text
SIGKILL = 9
→ 즉시 강제 종료
→ 프로세스가 처리하거나 무시할 수 없음

SIGSTOP = 19
→ 강제 정지
→ 프로세스가 처리하거나 무시할 수 없음

SIGTERM = 15
→ 정상적인 종료를 요청
→ 프로그램이 처리할 수 있음

시험 포인트 ​

보기 중 다음 Signal의 번호를 비교하는 문제가 나올 수 있다.

text
SIGINT  = 2
SIGKILL = 9
SIGQUIT = 3
SIGSTOP = 19

따라서 위 네 개 중 가장 큰 Signal 번호는 SIGSTOP이다.

키보드와 Job 제어 Signal은 묶어서 기억한다.

text
Ctrl+C → SIGINT  = 2  → 종료
Ctrl+\ → SIGQUIT = 3  → 종료 + Core Dump
Ctrl+Z → SIGTSTP = 20 → 정지

SIGSTOP = 19 → 무조건 정지
SIGCONT = 18 → 실행 재개

번호 암기 흐름:

text
1 HUP → 2 INT → 3 QUIT
9 KILL → 15 TERM
17 CHLD → 18 CONT → 19 STOP → 20 TSTP

SIGKILL(9)과 SIGSTOP(19)은 프로세스가 포착(catch), 차단(block), 무시(ignore) 할 수 없는 유일한 표준 Signal이다.

5. 프로세스 종료 및 검색 ​

kill ​

PID를 지정하여 Signal을 보낸다.

bash
kill PID
kill -9 PID
kill -TERM PID

기본 Signal은 SIGTERM(15)이다.

bash
kill 513

→ PID 513에 SIGTERM 전달

killall ​

프로세스 이름을 기준으로 Signal을 보낸다.

bash
killall httpd

→ 이름이 httpd인 프로세스를 종료

pgrep ​

프로세스 이름이나 조건을 이용해 PID를 검색한다.

bash
pgrep httpd

pkill ​

프로세스 이름이나 조건을 기준으로 Signal을 보낸다.

bash
pkill httpd

비교 ​

명령기준역할
killPIDSignal 전달
killall이름해당 이름의 프로세스에 Signal 전달
pgrep이름/조건PID 검색
pkill이름/조건Signal 전달

문제 유형 ​

bash
(    ) httpd

가능:

bash
killall httpd
pgrep httpd
pkill httpd

불가능:

bash
kill httpd

kill은 기본적으로 프로세스 이름이 아니라 PID를 사용한다.

6. 프로세스 우선순위 ​

리눅스에서는 프로세스 스케줄링 우선순위와 관련하여 PRI와 NI 값을 사용한다.

NI: Nice Value ​

사용자가 조절할 수 있는 우선순위 값이다.

범위:

text
-20 ~ 19
text
NI 값 낮음 → 우선순위 높음
NI 값 높음 → 우선순위 낮음

예:

text
NI = -10 → 높은 우선순위
NI = 0   → 기본값
NI = 10  → 낮은 우선순위

PRI: Priority ​

커널이 스케줄링에 사용하는 실제 우선순위 값이다.

일반적으로 사용자가 직접 조절하는 값은 NI이다.

7. nice와 renice ​

nice ​

새로운 프로세스를 실행하면서 NI 값을 지정한다.

bash
nice -n 10 command

예:

bash
nice -n 10 ./program

→ 낮은 우선순위로 새로운 프로그램 실행

renice ​

이미 실행 중인 프로세스의 NI 값을 변경한다.

bash
renice -5 -p 513

→ PID 513 프로세스의 NI 값을 -5로 변경

일부 환경에서는 다음 형태도 사용한다.

bash
renice -5 513

비교 ​

명령대상
nice새로 실행할 프로세스
renice이미 실행 중인 프로세스

주의 ​

문제에서

text
PID = 513
현재 NI = 0
NI 값을 -5로 변경

이라고 하면 기존 프로세스이므로 renice를 사용한다.

bash
renice -5 -p 513

8. 한 번에 정리 ​

text
프로세스 생성
├─ fork     → 프로세스 복제
└─ exec     → 실행 프로그램 교체

Job Control
├─ jobs     → Job 확인
├─ fg       → Foreground
├─ bg       → Background
└─ nohup    → 로그아웃 후에도 실행

프로세스 검색/종료
├─ kill     → PID 기준 Signal
├─ killall  → 이름 기준 Signal
├─ pgrep    → 이름/조건 → PID 검색
└─ pkill    → 이름/조건 → Signal

우선순위
├─ PRI      → 커널 스케줄링 우선순위
├─ NI       → 사용자가 조절하는 Nice 값
├─ nice     → 새 프로세스
└─ renice   → 실행 중인 프로세스

Signal
├─ 종료 요청  → SIGINT(2), SIGTERM(15)
├─ 강제 종료  → SIGKILL(9)
├─ 상태 알림  → SIGCHLD(17)
├─ 실행 재개  → SIGCONT(18)
├─ 강제 정지  → SIGSTOP(19)
└─ 터미널 정지 → SIGTSTP(20)
